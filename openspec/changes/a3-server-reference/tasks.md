Ordered clusters. Each cluster is a clean stopping point: land it, run `pnpm check`, commit, push, stop if the session is done. Within a cluster each numbered task is independently committable. Sized for two implementer sessions (a natural break falls after Cluster 3).

## Cluster 1 — storage contract + in-memory store

- [x] 1.1 `src/store.ts`: the pluggable persistence interface — the contract Rennet's B4 plugs into. Promise-returning, log + schema only: create a board (id + wire schema), read a board's schema (`undefined` for unknown), **atomic append** of `{actor, op}` entries that assigns contiguous seqs starting at 1 (a batch's events land contiguously or not at all; append returns the appended events with their seqs), and read events after a given seq in order. No projection methods — state is always derivable from the log. No database dependencies, Node stdlib + `@whtbrd/core` types only.
- [x] 1.2 `src/store.ts` (same file): `InMemoryBoardStore`, the reference implementation. Tests: seqs contiguous from 1 across multiple appends; events read back in order and filtered by after-seq; unknown board reads return `undefined`/empty per the contract. Commit.

## Cluster 2 — projection fold

- [x] 2.1 `src/project.ts`: pure deterministic fold from an ordered event list to board state — `create` inserts the element, `update` shallow-merges the op's `data` keys into the element's `data`, `delete` removes it. Expose the projected elements (id → element) and the id → kind map core's `validate()` takes as `existing`. No I/O, no store dependency — a function of events alone.
- [x] 2.2 Tests: fold determinism (same events, deep-equal state), shallow-merge semantics (untouched keys survive, supplied keys overwrite, undeclared passthrough keys survive), delete removes, create-after-delete of a different id, within-batch mint-then-update-then-reference. Commit.

## Cluster 3 — the board service

- [x] 3.1 `src/service.ts`: the embeddable service over a `BoardStore` (defaulting to a fresh `InMemoryBoardStore`). `createBoard(schema)` → mints `board_id` via `crypto.randomUUID()`, stores the schema; `getSchema(board_id)`; `describe(board_id)` → wire `DescribeResponse` (`protocol_version` from core); `getEvents(board_id, cursor?)` → wire `EventsResponse`: events with `seq > cursor` (default 0) in order, returned `cursor` = last served seq or the request's cursor when nothing new; `getState(board_id)` → the projection (library API for embedders — not a wire tool). Unknown `board_id` throws a plain `Error` everywhere (the closed enum belongs to apply validation only).
- [x] 3.2 `src/service.ts` `apply(board_id, ops, actor)` → wire `ApplyResponse`. In order: **dedup** — drop any op whose `op_id` already appears in the board's log or earlier in the same batch (per-op, before validation; an all-duplicate batch returns `{ok: true}` appending nothing); **validate** — core's `validate(schema, survivors, existing)` with `existing` fed from the projection (all-or-nothing; a rejection is returned verbatim and appends nothing); **append** — one event per surviving op, atomically, actor recorded on each. A projection/op-id cache is allowed only if rebuilt from the log and covered by 3.4's equivalence test; the lazy fold-per-call version is acceptable — do not optimize speculatively.
- [x] 3.3 Re-export the service, store interface + in-memory store, and projection fold from `src/index.ts` alongside the protocol-version exports.
- [x] 3.4 Tests: end-to-end create→apply→getState/getEvents; **dedup replay** (re-apply the same batch: `{ok: true}`, log length unchanged); mixed batch with one already-applied op (only the new op appends); **all-or-nothing** (mid-batch invalid op: exact code, state and log untouched); attribution (each event carries the actor passed to that apply); cursor paging across multiple applies; **projection-rebuild equivalence** (fold the raw store log independently, deep-equal the service's `getState`); unknown board throws. Commit.

## Notes

- The service is a library: no HTTP/WebSocket/stdio/MCP anywhere in this change (A4), no screenshot storage or rendering (A4 decides serving; schema + projection already expose everything a renderer needs), no Python (A6).
- Core's `validate` signature and the closed error enum are frozen — dedup stays out of core, and unknown-board is a thrown `Error`, not an enum code.
- No span/anchor/relation/presentation/attention concepts (#463 R27/R28): thread growth is ordinary append.
